# Amazon ML Entity Resolution: Final Optimization Pipeline

This document defines the strict 15-phase experimental protocol and execution strategy to transition from development experiments to the final full-scale production pipeline.

## ⚠️ Core Philosophy
1. **Candidate Recall is the ceiling.** Do not obsess over AUC on pairs that were artificially injected. Focus on candidate recall.
2. **Stop blind K-sweeps.** K=50 is the baseline. Do not increase K to 500. Instead, find out *why* K=50 missed the remaining 2.3% and build a specific blocker to catch it.
3. **RAM and Runtime are gates.** The full 10M S2/S3 universe must be tested at 50K S1 before authorizing the full 2.2M run.

---

## Phase 1 — Freeze the experimental protocol
- **Split Strategy:** 70% Train, 15% Validation, 15% Holdout (split by S1 entity, stratified by country).
- **Evaluation Criteria:** All experiments must be logged into a single table with: `Candidate Recall, AUC, Precision, Recall, Macro F0.5, Singleton Accuracy, Runtime, Peak RAM`.
- **Rule:** No experiment is considered "better" unless evaluated on the exact same holdout split.

## Phase 2 — Establish the REAL K=50 baseline
- Run the full S2/S3 stress test in your MASTER notebook.
- **Objective:** Measure candidate recall, RAM, and runtime when blocking 50K S1 against the **full 10.3M** S2/S3 records.

## Phase 3 — Attack the remaining blocking failures
- Extract all Ground Truth matches that were NOT found in the candidate set.
- Output to `reports/error_analysis/missed_blocking_matches.csv`.
- Create a frequency table of failure types:
  - Typo
  - Abbreviation
  - Word Order
  - Address Variation
  - Missing Address
  - Transliteration
  - DBA/Trade Name
- **Rule:** Do not guess what blocker to build until this table is generated.

## Phase 4 — Build independent blockers
Instead of one massive TF-IDF blocker, build cheap, independent routes:
- **Blocker A (Current):** Character TF-IDF Name.
- **Blocker B (Exact):** Normalized name inverted index.
- **Blocker C (Address):** Token inverted index on address (e.g. "bangalore 560001").
- **Blocker D (Numeric):** Extract PIN/ZIP/House number and do exact/prefix retrieval.
- **Blocker E (Rare Token):** Frequency-based inverted index on rare name tokens.

## Phase 5 — Union the blockers
- The final candidate generator merges the sets from Blockers A-E.
- This is the only way to recover the remaining misses without exploding K.

## Phase 6 — Evaluate blocking BEFORE LightGBM
- Calculate **Candidate Recall** for every blocking experiment independently.
- Example:
  - K50 Current: 97.7%
  - K50 + Exact: 98.1%
  - K50 + Address: 98.9%

## Phase 7 — Then optimize the matcher
- Use the candidate set produced by the **actual blocker**.
- Extract the 31+ features (Name distances, Address distances, Full Document distances, Structural ratios).
- **Honest Training Rule:** Train the model ONLY on actual candidate pairs generated by the blocker. Keep missed-by-blocking pairs strictly for diagnostic analysis, not model training.

## Phase 8 — Hard-negative mining
- Identify candidates that were ranked highly by blocking (very similar) but are negatives (e.g. identical name, different city).
- Force the model to train heavily on these hard negatives rather than obvious, easy negatives.

## Phase 9 — Threshold optimization
- The threshold is dynamic!
- When you change K, blocking, features, or negative sampling... **re-sweep the threshold**.
- Never carry `0.60` or `0.65` over blindly from a previous experiment.

## Phase 10 — Use the holdout properly
- **TRAIN:** Develop model.
- **VALIDATION:** Choose blocking, model, threshold.
- **HOLDOUT:** Final sanity check.
- **Rule:** Freeze configuration once you check the holdout. Do not repeatedly optimize against the holdout.

## Phase 11 — Decide whether full training needs all 2.2M S1
- Train on 50K, 200K, 500K, and 2.2M. Evaluate on the same untouched holdout.
- If 500K yields `0.975` and 2.2M yields `0.975`, there is no need to burn compute on the full dataset for training.

## Phase 12 — Full-data model
- Once everything is frozen (Blocker, Features, LGBM params, Threshold), train the final model using the validated data volume.

## Phase 13 — Full TEST inference
- Switch from TRAIN to TEST mode.
- Pass 1.73M Test S1 through the final blocker against the Full S2/S3 test universe.
- Generate features in batches, run inference with the frozen threshold.

## Phase 14 — Generate the two required files
- `candidate_pairs.tsv`: Must contain the actual final candidate set fed into the inference model.
- `matching_results.tsv`: Contains predictions for every test S1 exactly once (including empty strings for singletons).

## Phase 15 — Validation
- Run the official validator script before submission.
- Result must equal `PASS`.
