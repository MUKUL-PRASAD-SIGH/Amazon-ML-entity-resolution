# Audit Report: Amazon ML 2026 Business Entity Resolution Model

**Date**: 2026-09-25  
**Auditor**: Experimentation, Feature Analysis, & Decision-Policy Engineer  

---

## 1. Executive Summary

This audit establishes the baseline architectural inspection of the Business Entity Resolution pipeline. The goal is to maximize **Macro-Averaged $F_{0.5}$** across Source-1 ($S_1$) entities. 

The audit verified that:
1. **Validation Splitting**: Done strictly by $S_1$ entity ID, preventing pairwise data leakage.
2. **Feature Matrix**: Currently computes 17 pairwise similarity and length features using `rapidfuzz` and exact regex matching.
3. **Negative Sampling**: Hard negatives are drawn strictly from candidate pairs generated by TF-IDF blocking (`NEG_PER_POS = 5`).
4. **Leakage & Dev Sampling**: No data leakage from validation/holdout into training. Dev sampling (`--sample N`) reduces $S_2/S_3$ candidate pools to accelerate iteration, but full dataset metrics must be validated on 50K/full runs.
5. **Decision Policy**: Currently uses a single global probability threshold chosen by sweeping over $F_{0.5}$ on the validation set.

## 2. Pipeline Component Audit

### 2.1 Data Loading & Development Subsampling (`src/train_model.py:load_train_data`)
- **Data files**: `train_source1.tsv` (2.2M rows), `train_source2.tsv` (5.0M rows), `train_source3.tsv` (5.3M rows), `train_ground_truth.tsv`.
- **Dev Sampling (`--sample N`)**:
  - $S_1$ is randomly sampled to $N$ entities (`RANDOM_STATE = 42`).
  - $S_2$ and $S_3$ are filtered to include **all Ground Truth (GT) matches** for the sampled $S_1$ entities plus $5 \times N$ random extra records.
  - *Observation*: Keeping all GT matches in dev mode guarantees candidate recall isn't artificially ruined, but shrunken $S_2/S_3$ size makes candidate retrieval easier than full 5M blocking.

### 2.2 Preprocessing (`src/preprocess.py`)
- **Unicode NFKC normalization**: Applied to standardise scripts (Devanagari, Kannada, accented characters).
- **NaN Handling**: Explicit handling for both Python `None`/`np.nan` and string literals `'nan'` / `'NaN'`.
- **Abbreviation Expansion**: 30+ name abbreviations (e.g. `Corp` $\rightarrow$ `Corporation`, `Pvt` $\rightarrow$ `Private`) and 20+ address abbreviations (e.g. `Rd` $\rightarrow$ `Road`, `Ste` $\rightarrow$ `Suite`), plus French legal suffixes (`SAS`, `SARL`, `SA`).
- **Country**: Cleaned to lowercase string `country_norm`. Kept as an open-set string (never categorical or one-hot encoded) to handle unseen test countries like France.

### 2.3 Blocking & Candidate Generation (`src/blocking.py`)
- **Method**: Country-bucketed character 2–4 n-gram TF-IDF cosine similarity.
- **Top-$K$ Candidate Selection**: $K=50$ candidates per source ($S_2$ and $S_3$ queried separately, merged to up to $2K=100$ total candidates per $S_1$).
- **Fallback**: If an $S_1$ country is missing from $S_2/S_3$, falls back to a global TF-IDF index across all $S_2/S_3$ candidates.

### 2.4 Train / Validation Split (`src/train_model.py:split_s1`)
- **Split Ratio**: 80% Train, 20% Validation (`VAL_FRACTION = 0.20`), stratified by `country_norm`.
- **Unit of Split**: **$S_1$ Entity ID**.
  - All candidate pairs for $S_1 \in \text{Train}$ are in `X_train`.
  - All candidate pairs for $S_1 \in \text{Val}$ are in `X_val`.
  - **Verdict**: Correct. Zero pair-level leakage.

### 2.5 Pair Building & Ground Truth Labeling (`src/train_model.py:build_pairs`)
- **Positives ($y=1$)**: All ground-truth matches for $S_1$ that appear in blocking candidates. Any missed GT match is also added with label 1 to ensure positive representation.
- **Hard Negatives ($y=0$)**: Sampled randomly up to `NEG_PER_POS = 5` per positive pair from the non-GT blocking candidates for that $S_1$ entity.

### 2.6 Baseline Feature Matrix (17 Features) (`src/features.py`)
| # | Feature Name | Description |
|---|--------------|-------------|
| 1 | `name_ratio` | Levenshtein similarity ratio of normalized names |
| 2 | `name_token_sort` | Token-sort similarity ratio (word reordering) |
| 3 | `name_token_set` | Token-set similarity ratio (subset / extra words) |
| 4 | `name_partial` | Partial string ratio (catches prefixes/abbreviations) |
| 5 | `name_jaro_winkler` | Jaro-Winkler prefix-weighted string similarity |
| 6 | `name_jaccard_token` | Jaccard similarity of word tokens in names |
| 7 | `addr_ratio` | Levenshtein similarity ratio of normalized addresses |
| 8 | `addr_token_sort` | Token-sort similarity ratio of addresses |
| 9 | `addr_token_set` | Token-set similarity ratio of addresses |
| 10 | `addr_jaccard_token` | Jaccard similarity of word tokens in addresses |
| 11 | `addr_num_overlap` | Jaccard similarity of digit sequences in address |
| 12 | `country_match` | Binary match indicator ($1.0$ if country identical, $0.0$ otherwise) |
| 13 | `blocking_score` | Cosine similarity score from TF-IDF blocking |
| 14 | `name_len_s1` | Character length of $S_1$ normalized name |
| 15 | `name_len_s23` | Character length of $S_{2/3}$ candidate normalized name |
| 16 | `name_len_ratio` | Ratio of name lengths ($\min(l_1, l_2) / \max(l_1, l_2)$) |
| 17 | `addr_len_ratio` | Ratio of address lengths ($\min(l_1, l_2) / \max(l_1, l_2)$) |

### 2.7 Model Training & Evaluation Metric (`src/train_model.py`, `src/evaluate.py`)
- **Classifier**: LightGBM binary classifier (`objective="binary"`, early stopping on validation AUC).
- **Target Metric**: **Macro-Averaged $F_{0.5}$** across $S_1$ entities:
  $$F_{0.5} = \frac{1.25 \times \text{Precision} \times \text{Recall}}{0.25 \times \text{Precision} + \text{Recall}}$$
  - **Singleton Entities** (no true match): Empty prediction $\rightarrow 1.0$; Any false match $\rightarrow 0.0$.
  - **Non-Singleton Entities**: Standard $F_{0.5}$ formula.
- **Threshold Selection**: Single global threshold swept across $[0.20, 0.95]$ in steps of $0.05$ to maximize validation Macro $F_{0.5}$.

---

## 3. Key Findings & Opportunities

1. **Precision Penalization**: Macro $F_{0.5}$ weights Precision 4$\times$ as heavily as Recall ($\beta^2 = 0.25$). A single false merge on a singleton entity converts a potential $1.0$ score directly to $0.0$.
2. **Lack of Interaction Features**: The baseline model lacks interaction features that explicitly signal address conflicts (e.g. identical business names but conflicting street/building numbers).
3. **Absence of Intra-Entity Candidate Context**: The classifier scores each candidate pair independently. It has no awareness of whether a candidate is ranked #1 or #2, or whether there is a large probability margin between the top candidates for a given $S_1$ entity.
4. **Single Global Threshold Limitations**: A single threshold applies universally regardless of candidate score distribution, source reliability ($S_2$ vs $S_3$), or entity ambiguity.
